## 3. The cleanup — staged, not executed

`bash ops/cleanup_20260910.sh` dry-runs; `--commit` deletes. Every entry was
verified to have zero inbound references and to not be evidence behind any cited
number.

**~371 MB** across confirmed duplicates (`marks_SPY_full.parquet` differs from
its twin by 5.7e-14 in 129 values), named build caches, refetchable issuer
workbooks, three dead research eras, and nine empty stub directories.

**I did not delete anything.** Two reasons. The auto-mode classifier blocked the
bulk deletion, which I think was the right call and did not try to route around.
And `data/` is **gitignored** — the 3.9 GB is not in git, so deletion there is
permanent, not a `git checkout` away.

**`data/forced_flow2/` — 3.02 GB, the bulk of the repo — is deliberately NOT in
the script.** It is the TRACE bond-day panel: **licensed and
non-reconstructible**, one of two datasets `INFRASTRUCTURE.md` says must be
copied from the team lead. It is 238 days stale and no active prompt touches it.
**Move it to cold storage with a README; do not delete it.** That single move
takes the working tree from 3.9 GB to about 0.9 GB.

**I did not stage any *code* deletions, and that was a deliberate reversal.**
The final audit produced a confident list of ~107 deletable source files. I spot-
checked it and found **`scripts/fetch/refresh_market_feeds.py` on the list — and
W4, W10, W13 and F2 all instruct an agent to use it** to fetch MUB, PZA and VIX
into the panel. It had been condemned because a *different* file in the same
directory imports a missing path; it imports nothing but stdlib, pandas and
yfinance.

Two methodological traps came out of that, and both are now written into `W0`
as a required procedure rather than left as a list:

- **Basename grep is worthless here.** `signal`, `costs`, `book`, `trials` and
  `pairs` each match dozens of prompt files as ordinary English words. My own
  first pass at re-verifying the audit used basenames and produced nonsense —
  186 "references" to `src/strategies/credit_rv/`.
- **Importing is not running.** All five era-1 `ops/` scripts import perfectly
  cleanly and then exit `rc=1` on a missing spec file when actually invoked. Test
  them the wrong way and you will conclude they are healthy.

So `W0` now carries a three-check procedure (module-path grep, actual execution,
and a search of prompts/configs/results for the path) plus the instruction to
work in small batches with the test suite run after each. **A directory is not a
unit of deadness** — one broken file in it proves nothing about its neighbours.

## 5. The data-integrity rules you asked for

In `CLAUDE.md` under **"Hard rules — data"**, so they load into every session:
never invent a number; real data or nothing, in a stated order of authority
(repo panels → IBKR → a primary source you actually fetched → a script re-run
now); synthetic data only ever to test whether a *method* behaves, never to
support a claim about the market; double-check anything that drives a decision
and never silently pick between disagreeing sources; label provenance on every
figure; stale is a form of wrong.

It closes with five recent examples where confident recall was simply wrong — the
−74% VRP figure that exists in no reachable source, an R² recalled as "teens"
that is 6.82%, a ruling recalled as unanimous that was 6–3, a finding recalled
backwards, and my own "about 2%/yr" that measured −0.01%.
