# Can the CEF paper account see bonds? (RESEARCH_PLAN_2026-10-09 item 0.11)

**2026-10-11 20:03:34 UTC, cef paper account, read-only, `python3 scripts/ops/alpaca_bond_assets.py`:** `GET https://paper-api.alpaca.markets/v2/assets?asset_class=treasury` returned HTTP 200 with **0 rows**, and `GET .../v2/assets?asset_class=corporate` returned HTTP 200 with **0 rows**. There are no example symbols to show. The same two GETs, made inline 2 minutes and 51 seconds earlier (20:00:43 UTC), gave the same answer. **[V]**

**What this settles.** Through the Trading API this account lists no Treasury and no corporate bond. Both values are documented members of the `AssetClass` enum, so the empty answers are not a malformed request: the reference for `GET /v2/assets` lists `treasury` and `corporate` (fetched 2026-10-11). Alpaca's "Fixed Income" guide (`docs.alpaca.markets/us/docs/fixed-income-1`, fetched 2026-10-11) says bonds are offered to **Broker API partners**, and that "all trading and data retrieval is executed via the Broker API" (`/v1/assets/fixed_income/us_treasuries`, `/us_corporates`). This account is a Trading API paper account, so that endpoint is not reachable from it. **Cash bonds are not tradable here.** The 2026-10-09 ruling put "cash bonds ... through another broker" in bounds (`docs/SYSTEM.md` §5); this result points the same way. True on its date only.

**How it was read.** The script uses `quantt.broker.alpaca.AlpacaClient`'s HTTP session with the cef book's key, taken from the file named by `QUANTT_ENV_FILE`. It makes one GET for each `asset_class`, with no other parameters. Only the status code, the row count and the counts by class, status and tradable are printed. No account number, account ID or key was printed or recorded.
