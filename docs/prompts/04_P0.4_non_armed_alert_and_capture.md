### What "loud" has to mean

A book that is supposed to run unattended has exactly two acceptable states
at 18:30 ET on a trading day: it traded, or a human has been told why it
did not. "Wrote `ok_not_armed` to a JSON file" is neither. The fault on
2026-08-03→08-28 was not that the system misbehaved (preflight correctly
refused to trade on a wrong port); it was that the refusal was silent for
a month.

### Task

**1. Alert on not-armed.** In `launch_job.py`, after PREFLIGHT, when today
is a trading day (`ops/schedule/nyse_calendar.py`), `DRY_RUN=0`, and
`arm` is False: call the same alert path `ops/halt.py` uses, with subject
`QUANTT cef: NOT ARMED <date>` and the list of blocking checks and their
details in the body. Do **not** write `HALT.md` for this (a halt is a
human hard stop; a non-armed session is a soft fault that should retry
tomorrow). Write to the heartbeat as today, plus `"needs_human": true` and
`"blockers": [...]`. A `DRY_RUN=1` session is a human choice and does not
alert; say so in the log.

**2. Alert on silence.** The watchdog job (`JOBS["watchdog"]` in

collect job ran. Missing → alert `QUANTT: NO SESSION RECORDED <date>`. The
watchdog itself must be watched: if its own heartbeat is older than one
trading day, the dashboard state strip turns red (P0.3's freshness block
already reads `heartbeat.json`; add the `watchdog` key to the strip).
