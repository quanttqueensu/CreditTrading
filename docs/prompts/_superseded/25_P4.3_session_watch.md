## Paste from here

You are wiring session progress into the QUANTT CEF dashboard. Read the
session contract in `~/Library/Application Support/quantt/launch_job.py`
(phases REFRESH → PANELS → PREFLIGHT → TRADE → CAPTURE, each with its own
failure policy; CAPTURE unconditional), `ops/halt.py`, `ops/heartbeat.json`,
and P4.1 (the event bus and `/api/stream`).

### What the operator should see at 17:14 ET

A four-step strip on screen 1: REFRESH · PANELS · PREFLIGHT · TRADE ·
CAPTURE, each grey, then blue while running with its start time, then
green with its duration or red with its reason. Under it, the last twenty
lines of the session log, streaming. When TRADE finishes, screen 4's
"Tonight" card (P3.4) populates. When CAPTURE finishes, the journal link
appears. If nothing has started by 17:20 on a trading day, the strip is
amber: "session not started"; by 18:30, red, and P0.4's silence alert has
fired.

### Task

**1. Progress file.** In `launch_job.py`, at every phase transition,
write `ops/books/cef_live/session_progress.json` atomically (write to a
temp file, `os.replace`):

```
{"date": "2026-09-09", "job": "cef", "dry_run": false,
 "phases": [
   {"name": "REFRESH",   "status": "ok",      "started": "...", "ended": "...", "detail": "prices -> 2026-09-09, NAV -> 2026-09-08"},
   {"name": "PANELS",    "status": "ok",      ...},
   {"name": "PREFLIGHT", "status": "ok",      ..., "detail": "arm=True"},
   {"name": "TRADE",     "status": "running", "started": "..."},
   {"name": "CAPTURE",   "status": "pending"}
 ],
 "log_path": ".../cef_2026-09-09.log",
 "updated": "..."}
```

Statuses: pending / running / ok / skipped / failed, with `detail`. The
write is wrapped so it can never raise into the session. Non-trading days
write one record with `"status": "skipped_non_trading_day"`.

**2. Server.** The stat loop from P4.1 watches the progress file and the
current log path; on change, publish `session.progress` with the JSON and
`session.log` with the new lines (tail the file by byte offset; never
re-send). `/api/session` returns the current progress and the last 200
log lines for a cold page load.

**3. Screen 1 strip and log tail.** The strip as described; the log tail
in a monospace box, auto-scrolling, with WARNING and above highlighted.
Historic sessions: `#session/2026-09-04` shows that day's progress
record (keep the last 60 under `ops/books/cef_live/session_history/`;
`launch_job.py` copies the record there at CAPTURE end).

**4. The not-started states.** Purely client-side from the NYSE calendar
and the clock: amber after 17:20 ET, red after 18:30 ET, on a trading
day, when no record with today's date exists.

### Acceptance

- Run the job by hand with `DRY_RUN=1` and watch the strip move through
  the five phases with no page reload.
- Kill the job during TRADE (Ctrl-C) and confirm the strip shows TRADE
  failed with the exception text and CAPTURE still ran (it is
  unconditional; if it did not, that is a launch_job bug to report).
- The progress file is valid JSON at every instant (atomic replace).

### Do not

- Do not move any logic into the dashboard; it renders what the job
  writes.
- Do not let progress writing change the session's exit code or timing.
