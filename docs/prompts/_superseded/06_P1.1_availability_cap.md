### The mechanism, and why this is capture not prediction

The signal says short the richest names. Today that is the whole Nuveen
muni complex: NAD −8,129 shares, NEA −7,319, NVG −4,852, NZF −4,533, MHD
−5,862, MQY −2,089. IBKR's visible lendable pool for NAD is **3,000
shares**; NVG **20,000**. Our NAD short is already borrowed (the pool
excludes shares lent to us), but we cannot add, and a recall leaves
nothing to re-borrow. `borrow_capacity.py` measured that at $500k, 11.4%
of the desired short book is unbuildable; at $5m, 27.8%.

Cost and availability bind on different names (HYT is expensive at 10.56%
but plentiful at 2.5m; NAD is expensive and scarce), yet in this universe
scarce correlates with expensive. So a cap set by *availability* removes
mostly the *expensive* shorts, and the measured result is that the
constraint pays for itself: gross Sharpe 1.20 → 1.16, borrow drag 1.22 →
0.88%/yr, net-of-borrow 0.10 → 0.14 on the calendar. That is a rare thing:
a feasibility constraint that raises expected return.

This is TC work. The alpha is untouched; we are choosing to hold the part
of the ideal book we can actually finance.

### The construction

Let the frictionless target after demeaning and normalising be
$w^0_i$, $\sum_i w^0_i = 0$, $\sum_i |w^0_i| = 1$. Let $A_i$ be the
20-session rolling **minimum** of `available_shares` for name $i$ (a
snapshot is not a pool; the minimum is the conservative reading), $P_i$
the sizing close, $N$ the sleeve NAV, and $\phi = 0.25$ the fraction of the
visible pool we allow ourselves to be.

1. **Cap each short:**
   $$w^{cap}_i = \max\!\left(w^0_i,\; -\phi \frac{A_i P_i}{N}\right)
   \quad\text{for } w^0_i < 0.$$
   Longs are never capped; you can always buy.
2. **Rescale the long leg to the surviving short leg** so the book stays
   dollar-neutral:
   $$S = \sum_{i:\,w^{cap}_i<0} |w^{cap}_i|,\qquad
   L = \sum_{i:\,w^0_i>0} w^0_i,\qquad
   w^{cap}_i = w^0_i \cdot \frac{S}{L}\ \text{ for } w^0_i > 0.$$
   Gross is now $2S \le 1$. Do **not** re-normalise gross back to 1 here:
   the whole point is that the book is smaller when it cannot be financed.
3. **Vol scalar** is computed on the capped book exactly as today
   (trailing 63-day realised vol of $\sum_i w^{cap}_i r_i$, clipped 0.2 to
   2.5), so a smaller capped book gets a larger scalar up to the cap. State
   in the note that this partially offsets step 2 and report gross before
   and after.
4. **Min-weight filter and band** apply afterwards, unchanged. The band's
   reference is the capped target, so a name whose pool shrinks will be
   traded back to the band edge of its *new* capped target.

Where it goes in the sleeve: between the normalisation and the vol scalar,
behind a frozen-spec block:

```
"short_cap": {"phi": 0.25, "lookback_sessions": 20,
              "_note": "..."}
```

Absent block = today's behaviour, byte-identical (prove it).

Failure policy: a name in the universe with no borrow row inside the
lookback **raises** naming the ticker. Do not assume an unlimited pool;
do not assume zero. A name with `available_shares == 0` gets a short cap
of zero, which is a constraint, not a universe filter; count how often it
happens.

### The backtest, honestly labelled

The borrow panel is three days old. A backtest over 2005–2026 uses
*today's* pools held constant. That is the counterfactual "if today's
availability had held throughout", which is the right basis for a forward
decision and is **not** a historical test. Put that sentence at the top of
every table.

```
from scripts.cef.band_frontier import build_targets, band, evaluate
T, R = build_targets()                       # frictionless daily targets
T_cap = apply_short_cap(T, pools, prices, nav=capital)   # your function, per date
H_ref = band(T, 0.048)
H_cap = band(T_cap, 0.048)
```

Run for capital ∈ {$500k, $2m, $5m}. For each, report against the
reference:

| | gross SR | ann % | vol % | turn/yr | hold d | net@5 | net@15 | net@30 | borrow %/yr | net@15 − borrow | avg gross | unfillable % |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

Borrow drag per day: $\sum_i \max(-H_{it},0)\,\text{fee}_i/252$ with the
latest fee row. "Unfillable %" = the share of the *uncapped* desired short
notional that exceeds $\phi A_i P_i$ on that date, averaged.

Turnover-match: the cap changes turnover slightly; if $H_{cap}$ turns more
than 5% away from the reference, find the band width that matches and
report both.

Eras: 2005–09, 2010–14, 2015–19, 2020–22, 2023–26; the cap should cost
nothing in eras when the muni complex was not the short side, and that is
a sanity check on the mechanism.

Report which names' short weights are cut and by how much, per era, and
