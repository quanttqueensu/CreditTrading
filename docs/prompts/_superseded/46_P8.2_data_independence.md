### Prices: the broker is the source

We trade these 17 names through IBKR; its `reqHistoricalData` daily bars
(`whatToShow="TRADES"`, `useRTH=True`, `barSize="1 day"`) are the official
closes of the instruments we hold, from a session we already maintain, with
no ticker-mapping risk and no partial bars. yfinance becomes a cross-check.

1. `scripts/cef/fetch_prices_ibkr.py`: for every ticker in the panel (44),
   request the last 10 daily bars (pace: 44 requests, well under IB's
   60-per-10-minutes), normalise to the panel schema, and append with the
   same `drop_duplicates(keep="last")` discipline. Never write a bar dated
   today before 16:05 (the guard moves here). Own client id from
   `config/.env` (`DATA_CLIENT_ID`), documented next to the others.
2. **History check, once:** pull the full daily history IBKR serves for the
   44 (it goes back years for listed stocks) and compare close-by-close
   with the yfinance-built panel. Report the disagreement rate at > 1 tick
   by name and by year, and every disagreement > 1%. Splits: yfinance
   `auto_adjust=False` versus IB raw TRADES bars should agree; where they
   do not, find out which is right against the fund's own statement and
   write it down. Decide, with evidence, whether to **rebuild the panel
   from IBKR** or keep the yfinance history and switch the forward source.
   If the disagreement rate is under 0.1% and no disagreement exceeds a
   tick, keep the history; otherwise rebuild.
3. Cross-check rule, every session: for each (ticker, date) both sources
   report, |IBKR − yfinance| > 1 tick → log the pair, use IBKR, and count
   it in the heartbeat detail (`price_disagreements`). Three or more in one
   session → alert; it means a data problem on one side.
4. `fetch_daily.py` becomes NAV-only plus the completeness gate; its price
   path is deleted, not left as a fallback. If the gateway is down at
   refresh time there is no price for today's pair and the session stands
   down — which is correct, because it could not have traded either.

### NAV: three channels, one agreement rule

NAV originates at the sponsor and reaches every vendor through Nasdaq's fund
network. We read it three ways and require agreement:

- **A. yfinance `X{tk}X`** (today's source).
- **B. CEFConnect `pricinghistory/{tk}/1Y`** — dated daily rows (verified
  2026-09-08: 246 rows, agrees with A to the cent on 21 of 21 comparisons
  except AWF 11.22 vs 11.21). Never `DailyPricing`: it carries no date.
- **C. Nuveen first-party** for the six Nuveen names (NAD, NEA, NVG, NZF,
  MQY is BlackRock — check; JFR is Nuveen). Open the product page in a
  headless browser once, record the XHR endpoint the page calls for daily
  NAV, and call that endpoint directly with a fixture-backed test. If the
  endpoint is not stable or needs a session token, fall back to rendering
  the page and parsing, and mark the channel fragile in the log. Nuveen
  also runs CEFConnect, so B is already Nuveen-sourced; C is the check that
  B has not been re-rounded or delayed.

Agreement, per (ticker, date):
- All channels that report agree to the cent → write it.
- Disagreement of exactly one cent → write the sponsor value if C reports,
  else A; log the disagreement with all values.
- Disagreement > one cent, or A and B both missing → the name is
  **INCOMPLETE** for that date. A NAV we cannot confirm is not a NAV. The
  completeness gate then stands the session down for the day (or, under
  P8.1, the 12:00 retry looks again).

Record, per channel, the first session at which each (ticker, date) was
seen (`data/cef/nav_channel_log.csv`). After twenty sessions this is the
publication-time evidence the programme has never had; summarise it in the
note by sponsor.
