### What is wrong

Tonight's list is 13 orders. Twelve are `kind: dust`: PDO −143, NEA +27,
NVG +17, PDI −11, PCN −11, DSL +10, JFR +13, BIT +6, MHD −5, AWF +3, PFN −2,
MQY −1. Gross $3,019. Every one of them is on a name the band told us to
leave alone.

The cause is a round trip through two different prices. The band decides on
weights: it computes the held weight from the signal-date close (2026-09-03
for a signal dated 09-03), says "inside the band, hold", and returns that
weight as the target. The executor then converts the weight back to shares
using the sizing close (2026-09-04). Different price, different floor, a
handful of shares of difference, and a real MOC order goes out.

There is no minimum trade anywhere on the path. `_make_orders` reads
`spec["rebalance"]["min_trade_usd"]`, the frozen spec has no `rebalance`
block, so it is 0. `ibkr.py` has no minimum at all.

### Why it matters more than $3,019 suggests

- IBKR's minimum commission is $1 per order. Twelve orders is $12 a session
  before the spread. With half-spread on these names at 8–14bp on ~$250 per
  order, call it $15 a session, about $3,700 a year, **0.75% of the $500k
  book**. The band's net-of-borrow expectation is roughly 0.43 Sharpe at
  5.3% vol, about 2.3%/yr. The dust leak is on the order of a third of that.
- `results/cef/PREREG_BAND_2026-09-06.md` commits that **turnover is the
  primary readout** for the band: expected 17.6×/yr against 31.1 on the
  calendar. Twelve extra orders a session are not strategy turnover and will
  make the readout read wrong in the direction that says "the band is not
  working".
- Each dust order is a real fill in `broker_fills.csv` and a real row in
  `slippage.csv`. Sixty sessions of shortfall statistics (PLAN.md §7.1) would
  be dominated by $30 trades whose rounding-to-a-penny cost is not
  representative of the strategy's real trades.

### The fix

The correct fix is at the source. When the band decides HOLD, the sleeve
knows the exact held quantity (`holds[tk]`). Emit that as a **qty-expressed**
target instead of a weight. The executor's diff is then exactly zero
regardless of which close it sizes on. `PositionTarget` already supports
`qty`; the sign convention is: LONG carries positive qty, SHORT negative,
and `signed_qty()` returns the signed value.

Steps:

1. In the output loop of `target_positions`, for `band_note.get(tk) == "hold"`,
   build `PositionTarget(instrument=tk, side=LONG if q > 0 else SHORT,
   kind=ETF, qty=abs(q) with the side sign as the class requires, reason=...,
   meta={"order_type": ...})` where `q` is the held signed quantity from
   `market_state.holdings`. Keep the reason string
   `cef band hold: |gap|<=... w=...` so logs and the dashboard still explain
   it. If `q` is 0 for a HOLD (it cannot be; a HOLD with no position means
   `tgt` is inside the band of zero and the name should be FLAT), raise with
   the ticker rather than emit a zero qty.
2. Read `ibkr.py::_resolve_qty` again and confirm a qty target bypasses the
   price lookup, so an unpriced HOLD name (HYT on a lag day) no longer
   becomes "cannot size weight target". This also fixes half of P0.2 for the
   live path; read that prompt after this one.
3. **Prove the no-op.** Copy the frozen spec to the scratchpad, delete
   `band_width`, run `CEFDiscountSleeve.target_positions` for the last five
   trading days with `MarketState(holdings=<ledger positions>,
   extras={"sleeve_nav": <ledger nav>})` before and after your change, and
   diff the serialised targets. They must be byte-identical when the key is
   absent. Record the diff command and its empty output in the note.
4. **Belt and braces.** Add a `rebalance` block to
   `ops/specs/cef_discount.frozen.json`:

   ```
   "rebalance": {"min_trade_usd": <derived>,
                 "_min_trade_note": "..."}
   ```

   Derive the number rather than guess it: the notional N at which
   `$1 + N × half_spread_bp/1e4` equals 30bp of N, i.e. N = 1 / (30bp −
   hs) with hs the live median half-spread from `config/costs.yaml` for the
   17 names. Show the arithmetic in the note. Make `ibkr.py::place_targets`
   honour the same key `exec_ledger.py` already reads, applied to
   `|delta| × price`, never to option legs. A skipped order must be logged

5. **Verify on the live path without trading.** Re-run
