### Why one table

Today the same 17 names appear in three places with three column sets:
Holdings (shares, cost, last, value, unrealised), Signal (discount, z,
target weight, target shares, delta), Trades (held, target, delta, price,
notional). A trader has to hold three tables in their head to answer
"what is NAD doing and what happens to it tonight?". One row per name,
every column that carries a decision, sorted by what is about to happen.

### The columns, with their source

| column | definition | source |
|---|---|---|
| ticker, group | | universe.csv |
| side | LONG / SHORT / flat | broker snapshot qty |
| held wt | qty × last / sleeve NAV | broker snapshot, ledger NAV |
| target wt | the sleeve's frictionless target | `/api/signal` |
| gap | target − held | derived |
| **dist. to edge** | \|gap\| − band_width; negative = inside, will not trade; the default sort key ascending so the names closest to trading are on top | derived, band_width from spec |
| tonight | BUY/SELL n shares, or "hold" | `/api/trades` |
| z, discount % | | `/api/signal` |
| NAV age (bd) | | nav panel |
| price, 1c half-spread bp | 0.005 / price × 1e4 | price panel |
| ADV $m, participation % | our typical trade / ADV | price panel, turnover readout |
| fee %, pool, our short / pool | utilisation; red above 25% | cef_borrow.csv, snapshot |
| borrow $/yr | short MV × fee | derived |
| next ex-date | flag if within 2 sessions | distributions.parquet |
| unrealised $ | | broker snapshot |
| last fill vs decision bp | most recent session this name traded | slippage.csv / shortfall log |

Names in the frozen universe with no position stay in the table, flat, so
the trader sees what is about to enter. Names held by another book (the
null trader's ETFs) are not in this table; they are the account, not the
book.

Group subtotal rows (muni / multi / hy / loan): gross, net, n, borrow
$/yr, unrealised. A book total row.

Colour carries a verdict only: distance to edge within 1 point of
trading (warn), utilisation > 25% (crit), NAV age > `max_nav_age_bd`
(crit), tick bp > 10 (warn), ex-date tomorrow (warn).

Above the table, one line: "Held = broker snapshot at HH:MM:SS · ledger
agrees / N material breaks" from `/api/live`'s reconcile block.

### Server

`/api/blotter` assembles the rows from the cached panels (P0.3), the
borrow csv, the distributions parquet, the signal frame, the trades
diff, and the broker snapshot. One call. Each cell that cannot be
computed is `null` with a sibling `<col>_reason` string; the page renders
the reason on hover. No medians, no zeros for missing.

Sorting is client-side on any column; the default is distance to edge.
Clicking a ticker opens the per-name drill-down (P3.2; stub the route
now).

### Above the table: the valuation bar chart

Keep `drawZ` (the diverging bar of z against today's mean) as the only
chart on this screen, above the table, at 180px tall. Hovering a bar
highlights the row.
