### The defects, each verified during the 2026-09-07 review

**D1. Null dereference when the broker is down.** `loadLive()` in
`index.html` (~line 826) has, in its `!d.ok` branch,
`$("#bookExp").innerHTML = nodata(...)`. There is no element with id
`bookExp`. `$()` returns null, the assignment throws, and the rest of the
branch (clearing `#reconcile`, `#recChip`, `#attrProblems`, calling
`drawState()`) never runs. The state strip keeps showing the last good
reconcile state on a page whose broker is unreachable. Verify by stopping
the gateway or pointing a copy of `config/.env` at a closed port, then
watching the console.

**D2. Undefined severity classes.** `loadFactors()` uses
`chip ${sev}` with `sev = "bad"` and `tileEl(..., "neg")`;
`drawScoreboard()` uses `chip bad`. The CSS defines `.chip.crit` and
`.down`, not `.bad` or `.neg`. Result, visible in the Positions tab today:
the top "Effective breadth 1.17" tile is red (it uses `down`), the
risk-card "EFFECTIVE BREADTH 1.17" tile is white, and the "BR_eff 1.17 of
17" chip is grey. The single most important risk number on the page
renders as neutral in two of its three places.

**D3. Three transient broker connections.** `_probe_broker()` opens an
IB session with clientId 205 (8s timeout, 20s cache). `_portfolio()` opens
clientId 302 for every `/api/live` call (4s cache) **and** again under the
`factor_pos` cache key for `/api/factors`. The page polls `/api/live` every
5 seconds, so the server connects and disconnects from IB Gateway roughly
every 5 seconds forever. During the review the header showed "Broker down
127.0.0.1:4002" in one screenshot while the Positions tab, taken seconds
later, showed "Broker connected" and 34 live positions. The account was
fine; the probe collided with a concurrent connect.

**D4. Panels re-read parquet on every call.** `_signal_frame()`,
`api_trades()`, `_decompose()`, `_br_history()` and `_freshness()` each
call `pd.read_parquet` on `data/cef/cef_prices.parquet` (266k rows) and
`cef_nav.parquet`. `/api/factors` runs `_decompose` once per session in
`_br_history` for 40 sessions. `/api/verify` runs preflight, which probes
the broker again.

**D5. Sequential client fetches.** `loadSlow()` awaits `/api/signal`, then
`/api/benchmarks`, then `/api/provenance`, then eight draw steps, in
sequence. First paint waits on the slowest.

**D6. Network fonts on a local-only page.** Inter and JetBrains Mono load
from fonts.googleapis.com. On a machine without internet, or with the
gateway's network rules, the page falls back to system fonts mid-render.

### Task

**1. One broker session, owned by the server.**

Build a `BrokerSnapshot` class in a new `dashboard/broker_session.py`:

- One `ib_async.IB()` connection, `readonly=True`, a single clientId taken
  from `config/.env` (add `DASHBOARD_CLIENT_ID`, default 900; document why
  it must not collide with the scheduled jobs' ids in `ops/schedule/*.env`).
- Runs in a background thread with its own asyncio loop. Connects at server
  start, reconnects with exponential backoff (2s → 60s) on drop, and never
  raises into a request handler.
- Subscribes to `updatePortfolioEvent`, `accountSummaryEvent`,
  `openOrderEvent`, `orderStatusEvent`, `execDetailsEvent`. On each event,
  updates an in-memory snapshot under a lock: positions (symbol, qty, avg
  cost, market price, market value, unrealised), account summary tags
  (NetLiquidation, GrossPositionValue, TotalCashValue, ExcessLiquidity,
  Cushion, MaintMarginReq, AvailableFunds), open orders, today's fills, and
  `updated_at` per section.
- Exposes `snapshot()` returning a deep copy plus `ok`, `connected_since`,
  `last_error`, `endpoint`. If the connection is down, `ok: False` and the
  reason; **the last positions are still returned but stamped
  `stale: True` with their `updated_at`**, so the page can show them greyed
  with the time, never as live.
- `_probe_broker`, `_portfolio`, and the `factor_pos` cache are replaced by
  reads of the snapshot. `/api/status`, `/api/live`, `/api/factors`,
  `/api/verify`'s broker/margin checks all read it. `ops/preflight.py`'s own
  probe is left alone (it runs in the scheduled job, not here) but
  `api_verify` passes the snapshot to a new `want_probe=False` argument if
  preflight supports it, or skips the broker check and reports "checked via
  dashboard session" with the timestamp.
- `/api/connect` (the one POST) still starts the gateway via IBC. After it
  returns, the session thread will reconnect on its own.

Test: run the server, `watch -n1 curl -s :8787/api/status`, restart the
gateway, and confirm the header goes down and back up once, with no
flicker, and that `ps` shows one Python process holding one socket to port
4002.

**2. Fix D1 and D2.** Remove the `#bookExp` reference (or add the element if
the exposure card is wanted; it is not, the Positions tiles carry it). Map
`bad` → `crit` and `neg` → `down` in JS, or add the CSS aliases; pick one
and grep for any other undefined class. Then simulate broker-down and
confirm every panel degrades independently and the state strip updates.

**3. Cache the panels by mtime.** A `PanelCache` in `server.py`: loads
`cef_prices.parquet`, `cef_nav.parquet`, `cef_universe.csv`,
`cef_borrow.csv`, `cef_distributions.parquet` once each, keyed on
`(path, st_mtime_ns)`, re-loads when the mtime changes, shared by every
endpoint. The pivoted frames (`px`, `nav`, `vol`, `disc`) are cached too,
since three endpoints pivot the same thing. No TTL: the file's mtime is the
truth. Log a line when a reload happens.

Measure before and after: a 20-request loop against `/api/signal`,
`/api/trades`, `/api/factors`, `/api/verify` with `curl -w '%{time_total}'`;
report p50 and p95 for each in the commit message.

**4. Parallel client fetches.** In `loadSlow()`, fire `/api/signal`,
`/api/benchmarks`, `/api/provenance`, `/api/pnl`, `/api/trades`,
`/api/factors` with `Promise.allSettled`, then run the draw steps. Keep
`step()`'s per-panel error isolation; a rejected promise renders that
panel's `nodata()` and nothing else.

**5. Vendor the fonts.** Download Inter (400/500/600/700) and JetBrains
Mono (400/500/600) as woff2 into `dashboard/static/fonts/`, add
`@font-face` rules with `font-display: swap`, remove the Google Fonts
`<link>`s. Confirm the page renders identically offline.

**6. Regression pass.** Every endpoint's JSON must be unchanged in shape
except for the new `stale`/`updated_at` fields; diff a capture of each
endpoint before and after with the volatile fields stripped. Run
`python3 -m pytest src -q`.
