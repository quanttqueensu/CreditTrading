### The problem

The ledger was re-seeded from broker positions on 2026-09-08. The Book
tab shows NAV $500,000, P&L $0, return 0.00%, and five tiles of "n/a" with
a banner explaining that a return needs two sessions. That is honest and
useless. A PM opening the page today already knows things that are not on
the screen:

- the broker's intraday unrealised P&L by name and by group (in
  `/api/live` now: +$61 on the CEF book at the last snapshot);
- that only two sessions ever had broker fills (2026-07-31: overnight
  market orders, 120.6bp; 2026-09-01: MOC, 2.8bp) and what that says
  about the 32.6bp breakeven;
- the borrow bill on the current book in dollars per year;
- the pre-registered expectations the band will be judged on (turnover
  17.6×/yr, hold ~12 days) and that 0 of 20 sessions have accrued;
- what the backtest expects the NAV line to do, so that when it starts
  moving there is a reference band to read it against.

### The screen

Top row, one KPI strip (six tiles max):

| NAV (ledger) | Intraday P&L (broker, live) | Confirmed sessions / traded sessions | Realised cost, MOC sessions (mean ± SE vs 32.6) | Realised turnover ×/yr vs 17.6 | Borrow drag $/yr (current book) |

Each tile carries its source and as-of in the hover title; the intraday
tile is stamped with the snapshot time and greys when the broker session
is down.

Middle: **the NAV card**, unchanged in spirit. The line breaks at the
first modelled session; the provenance strip under it. Add a shaded
reference band around the NAV line: the backtest's expected path at the
band policy's ann return and vol (from
`evaluate(band(T,0.048), R)`: ann % and vol %), drawn as mean ± 1 sd
growing with √t from the epoch date, **labelled "backtest reference, not a
forecast, survivor-only panel"**. When there is one NAV row the band still
draws from the epoch, so the card is never empty.

Bottom: **the pre-registered readouts card** (P1.4 builds the data; stub
the card now reading whatever exists): four rows, each with expected,
realised, n of 20 sessions, and a state (not enough data / on track /
review).

Right rail or second row: **cost to date**, the two sessions as two rows
with method, fills, modelled, realised, excess; the abandoned method
struck through with its reason; the running MOC mean with its SE, and the
number of sessions to reach SE ≤ 1bp at the observed dispersion.

### Server

- `/api/real`: one payload with `nav`, `provenance`, `intraday` (from the
  broker snapshot, restricted to the CEF universe, by name and by group),
  `cost` (from `results/cef/shortfall_sessions.csv` when it exists, else
  from `slippage.csv` split by method), `turnover` (from
  `results/cef/turnover_readout.csv` when it exists), `borrow` (weighted
  fee and $/yr from `cef_borrow.csv` × current short MV), `reference`
  (ann return, vol, computed once from the harness and cached on disk in
  `results/cef/reference_band.json` with the run date; recomputed when
  the price panel's mtime changes by more than a month).
- Every block carries `asof` and `source`. A block that cannot be built
  carries `reason`.

### Acceptance

- With one NAV row: the screen shows six tiles with real values (NAV,
  intraday, 0/0 sessions, "2 MOC sessions, SE too wide", "0 armed
  sessions", the borrow figure), the NAV card with the reference band, the
  readouts card in "not enough data" state, the cost card with two rows.
  No tile says n/a.
- With the broker down: the intraday tile greys with the last snapshot
  time; everything else unchanged.
- No number on this screen is computed in JavaScript; the server states
  it with its source.

### Do not

- Do not present the reference band as a prediction; the label is
  mandatory.
- Do not fabricate a return from the intraday unrealised; it is a mark,
  not a session.
