# P4.1 — Push, not poll: one broker session, server-sent events, file watching

**Lever:** a monitor whose top is actually live. **Trials:** 0. **Touches
the live book:** no.

---

## Paste from here

You are making the QUANTT CEF dashboard event-driven. P0.3 must already
be done: the server owns one long-lived read-only `ib_async` session in a
background thread and exposes a locked in-memory snapshot. Read
`dashboard/broker_session.py`, the polling block at the bottom of
`dashboard/static/index.html` (`setInterval` every 5s for `/api/live`, 30s
for status, 120s for the slow panels, 300s for checks), and
`dashboard/server.py`'s `cached()` helper.

### Why polling is the wrong shape here

The broker moves on events (a fill, a mark update every few seconds
during RTH, an order status change). The ledger moves once a session,
when the scheduled job writes `nav.csv`, `positions.csv`,
`heartbeat.json`, `book_status.json`. The plumbing checks move slower
still. One interval either hammers the gateway or leaves live numbers
stale, and today the page does both: `/api/live` every 5s (which, before
P0.3, reconnected to IB each time) and `/api/trades` never unless the tab
is opened.

The right shape: the server knows when something changed; it tells the
page; the page redraws that card. Anything that did not change is not
redrawn and is not re-fetched.

### Task

**1. Event bus in the server.** A small in-process pub/sub
(`dashboard/events.py`): `publish(topic, payload)`; subscribers are
per-client `queue.Queue`s. Topics:

- `broker.positions`, `broker.account`, `broker.orders`, `broker.fills`,
  `broker.state` (connected / disconnected with reason): published by the
  broker session thread from its `ib_async` event handlers
  (`updatePortfolioEvent`, `accountSummaryEvent`, `openOrderEvent`,
  `orderStatusEvent`, `execDetailsEvent`, `connectedEvent`,
  `disconnectedEvent`). Coalesce bursts: at most one `broker.positions`
  event per 500ms, carrying the whole snapshot section.
- `ledger.changed` with the file name: a 2-second `os.stat` loop over
  `ops/books/cef_live/_ibkr_shadow/cef_discount/{nav,positions,orders,
  trades,broker_fills,slippage}.csv`, `ops/heartbeat.json`,
  `ops/books/cef_live/book_status.json`, `data/cef/cef_borrow.csv`, and
  the price/NAV parquets. No external watcher library; a stat loop is
  enough and it is obvious.
- `panel.<name>` after the server recomputes a cached panel because its
  inputs changed (`signal`, `trades`, `factors`, `provenance`, `verify`,
  `risk`, `doctor`): the PanelCache from P0.3 subscribes to
  `ledger.changed` and `broker.positions` and recomputes lazily; publish
  when done.
- `heartbeat` every 15s with the server time, so a stalled stream is
  visible.

**2. `/api/stream`.** A Flask route returning `text/event-stream`, one
generator per client, reading from that client's queue, formatting
`event: <topic>\ndata: <json>\n\n`. On connect, send a `snapshot` event
with the current state of every topic so the page never starts blank.
Handle client disconnect by removing the queue. Cap queue size; if a
client falls behind, drop to the latest snapshot rather than buffering
forever.

**3. Client.** Replace the intervals with one `EventSource("/api/stream")`.
Each card registers for topics; on an event it redraws itself from the
payload (or fetches its endpoint if the payload is a notification only).
`broker.state` drives the masthead chip and greys the live columns with
the last `updated_at` when disconnected. If `EventSource` errors twice in
a row, fall back to the old polling at the old intervals and show a
"polling" tag in the footer; retry the stream every 60s.

**4. Per-card "as of".** Every card shows its own event's timestamp in
the corner, from the event payload, not from `Date.now()`. A card that
has not received an event in longer than its expected cadence (positions
30s during RTH, ledger one session) marks itself stale.

**5. Tests.**
- A pytest that starts the server in a thread with a fake broker session
  publishing a positions event, connects an SSE client, and asserts the
  event arrives within 1s with the right shape.
- A manual test written into the note: copy `positions.csv` to a temp
  path, edit one share count, move it back, and confirm the blotter row
  flashes within 3s with no reload.

### Acceptance

- `ps`/`lsof` shows one socket to port 4002 from the dashboard process,
  and no periodic reconnects in IB Gateway's log.
- With the page open for an hour during RTH, the network tab shows one
  long-lived request plus on-demand fetches, not 720 `/api/live` calls.
- Killing and restarting the gateway produces exactly one disconnected
  and one connected event on the page.

### Do not

- Do not add WebSockets, socket.io, or a second process; SSE over the
  existing Flask app is enough and it stays read-only.
- Do not let an exception in an event handler kill the broker session
  thread; log and continue.
